Points Clés de l'Implémentation — src/config/settings.py

1. Classes, Fonctions et Méthodes Implémentées

Le fichier src/config/settings.py centralise la configuration du pipeline à l'aide de pydantic-settings, offrant un chargement automatique depuis les fichiers .env et une validation stricte du typage.

Énumérations & Sous-Modèles de Configuration
  • Environment : Énumération des profils d'exécution (DEVELOPMENT, PRODUCTION, TESTING, STAGING).
  • LogFormat : Formats d'affichage des journaux (JSON, TEXT, COLORED).
  • DatabaseConfig : Configuration AsyncPG / PostgreSQL (pool, overflow, timeouts, mode SSL).
  • RedisConfig : Paramètres de connexion au cache Redis, retries et timeouts socket.
  • LLMConfig : Configuration des modèles Ollama (deepseek-coder, nomic-embed-text, fenêtre contextuelle, température).
  • ChromaConfig : Connexion et paramètres de requêtage à la base vectorielle ChromaDB.
  • APIConfig : Configuration du serveur Web API FastAPI (CORS, workers, limites de corps HTTP).
  • SecurityConfig : Paramètres JWT, rate-limiting, HTTPS et listes d'IPs (allowed/blocked).
  • LoggingConfig : Niveau de sévérité, chemin de fichier journal, rotation de logs et indentation JSON.
  • CircuitBreakerConfig : Seuils d'échec/succès et timeouts pour le coupe-circuit.
  • PipelineConfig : Timeouts d'outils Web3 (Slither, Foundry, Halmos) et parallélisme des tâches.
Classe Principale Settings(BaseSettings)
  • Validateurs de Configuration :
    • validate_storage_path(v) (@field_validator) : Convertit le chemin en objet Path et crée automatiquement le répertoire s'il n'existe pas.
    • validate_environment(self) (@model_validator) : Valide la cohérence globale (ex: lève une erreur si debug=True ou test_mode=True en profil PRODUCTION).
    • validate_supported_chains(v) (@field_validator) : Vérifie que la liste des chaînes supportées appartient au périmètre autorisé (Ethereum, Polygon, Arbitrum, Solana, etc.).
  • Méthodes Utilitaires & Getters :
    • get_workspace_path(subpath) -> Path & get_storage_path(subpath) -> Path : Génération de chemins absolus sécurisés dans le workspace ou le stockage.
    • get_chain_rpc_url(chain) -> Optional[str] : Résolution dynamique de l'URL RPC selon la blockchain demandée.
    • get_github_auth() -> Dict[str, str] & get_github_token() -> str : Extraction sécurisée du token SecretStr GitHub et du nom d'utilisateur.
    • get_database_url(), get_redis_url(), get_ollama_url(), get_chroma_host(), get_chroma_port(), get_api_url(), get_log_level(), get_env_prefix(), get_max_retries(), get_verification_timeout() : Métriques et accesseurs de sous-configurations.
    • is_production(), is_development(), is_testing(), is_debug() -> bool : Prédicats de contrôle de l'environnement d'exécution.
    • to_dict(show_secrets=False) -> Dict[str, Any] : Export de la configuration en dictionnaire avec masquage automatique des secrets (***HIDDEN***).
Fonctions Globales & Initialisation
  • load_settings(env_file, env_prefix) -> Settings : Charge un fichier .env spécifique et instancie la configuration.
  • reload_settings() -> None : Recharge l'instance singleton globale settings à chaud.
  • get_settings_for_env(env) -> Settings : Bascule temporairement sur un profil donné et retourne sa configuration.
  • setup_logging(settings) -> None : Initialise les handlers de logs (console colorée, formateur JSON, rotation de fichier journal) selon la configuration.
  • settings : Instance globale unique (Singleton) initialisée à l'importation.

2. Bonnes Pratiques Appliquées

  • Masquage des Secrets (SecretStr) : Utilisation de SecretStr pour tous les jetons d'accès, mots de passe et clés API (GitHub, Sentry, Infura, S3), empêchant toute fuite accidentelle dans les logs.
  • Validation Cohérente à Froid & à Chaud : Combinaison de validation de champ (@field_validator) et de validation globale (@model_validator) garantissant l'impossibilité de lancer l'application dans un état incohérent (ex. mode Debug en Production).
  • Isolation par Profils : Support de préfixes de variables d'environnement et basculement à chaud via des profils dédiés (Dev, Staging, Prod, Test).
  • Création Automatique de l'Arborescence : Création automatique et transparente des répertoires systèmes requis (workspace, storage, logs) au moment de la validation.
  • Conformité Twelve-Factor App : Strict respect du stockage de la configuration dans l'environnement via pydantic-settings.

3. Points Remarquables

  • Support Multi-Storage & Observabilité Native : Prise en charge native du stockage local, S3 et GCS, couplée au support de Prometheus, Sentry et OpenTelemetry.
  • Gestion Intelligente du Format de Logging : Intégration d'un formateur structuré JSON pour la production et coloré (colorlog) pour le développement local.
  • Modularité via Sub-Models : Découpage propre de la configuration globale en 9 sous-modèles thématiques (Database, Redis, LLM, Security, API, etc.).
