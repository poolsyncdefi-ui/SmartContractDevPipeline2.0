1. Classes, Fonctions et Méthodes Implémentées

Le fichier src/models/execution_log.py définit le modèle ORM SQLAlchemy pour la table execution_logs, assurant la traçabilité complète, l'audit, le débogage et l'analyse de performance des actions d'agents, appels LLM et sorties d'outils[cite: 10].

Énumérations Typées
  • LogLevel : Niveaux de sévérité du journal (DEBUG, INFO, WARNING, ERROR, CRITICAL)[cite: 10].
  • LogCategory : Domaines métier du log (AGENT, LLM, COMPILATION, TEST, SECURITY, DEPLOYMENT, WORKFLOW, SYSTEM, USER, CUSTOM)[cite: 10].
Modèle Principal ExecutionLogModel(Base)
  • Colonnes & Indexation : Identifiant auto-incrémenté, clé étrangère optionnelle task_id (avec suppression en cascade), agent_id, niveaux/catégories Enum, prompts LLM (prompt_sent, raw_response), sorties d'outils (tool_output), horodatages UTC, durées en ms et métadonnées de code source (source_file, source_line)[cite: 10].
  • Indexation Composite : Index simples et composites ciblés (task_id + level, agent_id + category) optimisant les requêtes de recherche et de filtrage fréquentes[cite: 10].
Gestionnaires de Contenus JSON & Tags
  • get_metadata() / set_metadata(metadata) : Desérialisation et sérialisation sécurisées des métadonnées JSON avec gestion de repli en cas d'erreur[cite: 10].
  • get_tags() / set_tags(tags) : Manipulation de la liste des étiquettes sérialisées en JSON[cite: 10].
  • add_tag(tag), remove_tag(tag), has_tag(tag) : Utilitaires dynamiques d'ajout, suppression et vérification de tags[cite: 10].
Méthodes Usines (Factories @classmethod)
  • create_log(...) : Usine générique d'instanciation de logs avec initialisation automatique des métadonnées et tags[cite: 10].
  • create_error_log(...) : Constructeur spécialisé pour les erreurs système avec marquage automatique au niveau ERROR[cite: 10].
  • create_llm_log(...) : Constructeur dédié à la traçabilité des échanges LLM (prompts et réponses brutes) au niveau DEBUG[cite: 10].
  • create_compilation_log(...) : Usine pour la captation du retour d'outils de compilation (ex: Forge) ajustant le niveau selon le succès[cite: 10].
  • create_security_log(...) : Usine pour les résultats de scanners de sécurité (ex: Slither) basculant en ERROR si des vulnérabilités sont détectées[cite: 10].
Mixin d'Intégration Agent LoggableMixin
  • set_log_callback(callback) : Configuration d'un callback asynchrone pour la persistance externe du log[cite: 10].
  • log_info(...), log_error(...), log_llm_call(...) : Interface haut niveau simplifiée permettant aux agents d'émettre des logs sans manipuler directement le modèle ORM[cite: 10].
  • _create_log(...) : Méthode interne acheminant le log vers le callback s'il est configuré[cite: 10].

2. Bonnes Pratiques Appliquées

  • Patron de Conception Usine (Factory Pattern) : Utilisation de méthodes de classe spécialisées (create_*_log) garantissant une création homogène et typée des journaux d'erreurs, d'appels LLM et de compilations[cite: 10].
  • Résilience à la Désérialisation JSON : Gestion explicite des exceptions json.JSONDecodeError dans la lecture des métadonnées et tags, évitant les interruptions en cas de données corrompues[cite: 10].
  • Optimisation des Modèles de Transfert (DTO) : Distinction entre to_dict() (complet) et to_short_dict() (allégé) pour optimiser l'empreinte mémoire lors du rendu de listes de logs[cite: 10].
  • Découplage des Agents via Mixin : Le pattern LoggableMixin permet d'injecter la capacité de journalisation dans n'importe quelle classe d'agent sans coupler directement la logique métier à la base de données[cite: 10].
  • Indexation Multi-Critères : Index composites optimisés sur les paires de colonnes fréquemment interrogées conjointement (ex: task_id + level)[cite: 10].

3. Points Remarquables
