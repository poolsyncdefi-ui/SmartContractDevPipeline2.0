Points Clés de l'Implémentation — src/db/migrations.py

1. Classes, Fonctions et Méthodes Implémentées

Le fichier src/db/migrations.py fournit une infrastructure complète de gestion du schéma de base de données PostgreSQL, supportant l'initialisation, le versioning, l'inspection asynchrone, les migrations séquentielles et les rollbacks[cite: 7].

Initialisation & Cycle de Vie du Schéma
  • init_models() -> None : Crée l'ensemble des tables définies dans la métadonnée SQLAlchemy ainsi que la table d'historique[cite: 7].
  • drop_models() -> None : Supprime intégralement les tables du schéma[cite: 7].
  • reset_models() -> None : Réinitialise la base de données via un enchaînement drop_models() puis init_models()[cite: 7].
Suivi de Versioning & Historique
  • _create_migration_history_table(conn) : Crée la table migration_history pour tracer l'auteur, la date, le statut et les scripts[cite: 7].
  • get_current_version() -> Optional[str] : Extrait la version active depuis alembic_version ou migration_history[cite: 7].
  • set_current_version(version, description, applied_by) -> None : Enregistre une nouvelle version de schéma dans les tables de suivi[cite: 7].
Inspection Asynchrone du Schéma
  • get_existing_tables() -> List[str] : Interroge la base via conn.run_sync(inspect) pour lister les tables[cite: 7].
  • table_exists(table_name) -> bool : Vérifie la présence d'une table[cite: 7].
  • get_table_info(table_name) -> Optional[Dict[str, Any]] : Inspecte les colonnes, clés primaires/étrangères et index d'une table[cite: 7].
  • column_exists(table_name, column_name) -> bool & index_exists(table_name, index_name) -> bool : Contrôle l'existence d'une colonne ou d'un index[cite: 7].
Utilitaires DDL Conditionnels
  • execute_migration(sql, params) -> None : Exécute une instruction SQL DDL de manière sécurisée et transactionnelle[cite: 7].
  • execute_migration_script(script_path) -> None : Lit et exécute un fichier .sql de migration par lot d'instructions[cite: 7].
  • add_column(...), drop_column(...), rename_column(...) : Manipulations de colonnes avec vérification préalable d'existence[cite: 7].
  • add_index(...), drop_index(...) : Création et suppression conditionnelle d'index SQL[cite: 7].
Pipelines de Migrations & Rollbacks Séquentiels
  • run_migrations(target_version) -> None : Chef d'orchestre exécutant automatiquement les migrations requises jusqu'à la version cible[cite: 7].
  • migration_v1_to_v2(), migration_v2_to_v3(), migration_v3_to_v4() : Migrations graduelles (ajout de métadonnées, création de la table artifacts, contraintes et index composites)[cite: 7].
  • rollback_to_version(target_version) -> None : Restaure une version antérieure en exécutant les rollbacks inverses[cite: 7].
  • rollback_v4_to_v3(), rollback_v3_to_v2(), rollback_v2_to_v1() : Fonctions de nettoyage et de rétrogradation du schéma[cite: 7].

2. Bonnes Pratiques Appliquées

  • Idempotence des Opérations DDL : Chaque modification de schéma (ajout de colonne, suppression d'index) vérifie au préalable l'état de la base pour éviter les erreurs d'exécution[cite: 7].
  • Introspection Non-Bloquante : Emploi de conn.run_sync() avec l'inspecteur SQLAlchemy pour réaliser les audits de schéma sans bloquer la boucle asyncio[cite: 7].
  • Gestion Strictement Transactionnelle : Encapsulation de toutes les modifications SQL dans des blocs `async with engine.begin()` assurant un commit/rollback automatique[cite: 7].
  • Audit & Traçabilité Complète : Conservation de l'historique complet des migrations appliquées (horodatage, script, utilisateur) dans la table migration_history[cite: 7].
  • Normalisation des Exceptions : Capture des erreurs de DDL et conversion centralisée vers l'exception applicative StorageError[cite: 7].

3. Points Remarquables

  • Moteur de Migration Bidirectionnel : Prise en charge native des montées de version (v1 vers v4) et des rollbacks descendants (v4 vers v1)[cite: 7].
  • Double Support Alembic & Custom History : Compatibilité mixte capable de lire le pointeur standard alembic_version ou la table détaillée migration_history[cite: 7].
  • Exécution de Scripts SQL Bruts : Fonction execute_migration_script permettant d'intégrer facilement des scripts DDL d'administrateurs BDD externes[cite: 7].
