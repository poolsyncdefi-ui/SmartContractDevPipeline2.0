Points Clés de l'Implémentation — src/security/threat_simulator.py

1. Classes, Structures de Données et Méthodes Implémentées

Le module src/security/threat_simulator.py agit au niveau 3 du bouclier de sécurité multi-couches en instanciant un fork local via Anvil et Foundry pour simuler dynamiquement des vecteurs d'attaques réels sur les contrats cibles[cite: 17].

Structures de Données & Modèles
  • AttackType(str, Enum) : Énumération des types d'attaques supportés (FLASH_LOAN, ORACLE_MANIPULATION, MEV, REENTRANCY, FRONT_RUNNING, SANDWICH, LIQUIDATION, GOVERNANCE, CUSTOM)[cite: 17].
  • AttackSeverity(str, Enum) : Niveaux de sévérité d'une vulnérabilité (CRITICAL, HIGH, MEDIUM, LOW, INFO)[cite: 17].
  • AttackResult(dataclass) : Structure détaillée du résultat d'une simulation (type, statut de vulnérabilité, sévérité, impact, remédiation, étapes, temps d'exécution, détails) avec conversion to_dict()[cite: 17].
  • ThreatReport(dataclass) : Rapport consolidé de la simulation globale incluant le nombre total d'attaques, le statut de validation, la sévérité globale et la liste des recommandations (avec méthode to_dict())[cite: 17].
Classe Principale : ThreatSimulator
  • Initialisation & Gestion d'Anvil :
    • __init__() : Configuration du port Anvil (défaut: 8545), des paramètres RPC, du chemin du projet Foundry et initialisation des métriques de simulation[cite: 17].
    • start_anvil() : Démarre le nœud local Anvil sous forme de sous-processus avec options de fork blockchain[cite: 17].
    • stop_anvil() : Interrompt proprement le processus Anvil (envoi de SIGTERM puis SIGKILL si nécessaire)[cite: 17].
    • _ensure_anvil() : Vérifie et garantit que le nœud Anvil est actif avant le lancement d'une simulation[cite: 17].
  • Simulations d'Attaques & Orchestration :
    • simulate_flash_loan_attack() : Simule un emprunt non garanti pour tester la résistance du contrat aux attaques par flash loan[cite: 17].
    • simulate_oracle_manipulation() : Génère une distorsion artificielle des prix sur un DEX/pair pour mesurer l'impact sur les oracles du contrat[cite: 17].
    • simulate_mev_attack() : Simule une extraction de valeur maximale (front-running / sandwich) autour des opérations du contrat[cite: 17].
    • simulate_reentrancy_attack() : Injecte des requêtes récursives pour évaluer la vulnérabilité aux attaques par réentrance[cite: 17].
    • run_full_threat_suite() : Exécute en parallèle la suite complète des simulations d'attaques et agrège les résultats dans un ThreatReport structuré[cite: 17].
  • Génération de Scripts & Parsing :
    • _build_flash_loan_script(), _build_oracle_manipulation_script(), _build_mev_attack_script(), _build_reentrancy_script() : Génère dynamiquement le code Solidity/Forge pour chaque vecteur d'attaque[cite: 17].
    • _run_forge_script() : Exécute le script Forge dans un dossier temporaire en ciblant le fork Anvil local via subprocess.run[cite: 17].
    • _parse_flash_loan_result(), _parse_oracle_manipulation_result(), _parse_mev_attack_result(), _parse_reentrancy_result() : Analyse les logs de sortie Forge pour extraire le verdict de vulnérabilité[cite: 17].
  • Statistiques & Lifecycle :
    • get_stats() : Retourne les données quantitatives sur les simulations (compte global, vulnérabilités trouvées, erreurs par type)[cite: 17].
    • cleanup() : Arrête Anvil et supprime les fichiers/répertoires temporaires générés[cite: 17].
    • to_dict() & __repr__() : Représentations sérialisables et lisibles de l'état du simulateur[cite: 17].
