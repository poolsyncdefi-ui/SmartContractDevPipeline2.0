Points Clés de l'Implémentation - src/core/exceptions.py

1. Classes et Fonctions Implémentées

  • Classes d'Exceptions Personnalisées (Hiérarchie) :
    • PipelineBaseException : Exception racine de l'ensemble du pipeline. Définit le contrat commun (error_code, message, details, timestamp).
    • ModelValidationError / SchemaValidationError : Échecs lors de la validation des schémas Pydantic ou du type des paramètres.
    • AgentExecutionError & SkillExecutionError : Erreurs survenant lors de l'exécution d'un agent ou d'une compétence particulière.
    • TaskExecutionError & TaskTimeoutError : Levées en cas d'échec d'une tâche dans le DAG ou de dépassement du temps limite d'exécution.
    • CircuitBreakerError / CircuitOpenError : Déclenchées lorsque le coupe-circuit s'ouvre pour protéger le système contre les cascades de pannes.
    • DeploymentError, ContractCompilationError & VerificationError : Erreurs spécifiques au cycle de vie Web3 (compilation Solidity, déploiement RPC, vérification Etherscan/Blockscout).
    • QualityGateError & SecurityValidationError : Non-respect des seuils de qualité (couverture, complexité) ou détection de vulnérabilités critiques (Slither/Mythril).
    • HumanValidationRequired & ApprovalRejectedError : Mises en pause du pipeline ou rejets dans le cadre des flux RLHF (Human-in-the-loop).
    • ConfigurationError : Absence ou invalidité d'une configuration (ex. project_config.yaml).
  • Fonctions Utilitaires & Handlers :
    • format_exception_to_dict(exc: Exception) -> dict : Formate n'importe quelle exception sous forme de dictionnaire JSON-friendly.
    • to_error_response(exc: PipelineBaseException, request_id: str = None) -> ErrorResponse : Convertit une exception en instance du modèle Pydantic ErrorResponse.
    • handle_pipeline_exception(func) : Décorateur centralisé pour intercepter, journaliser (logging) et ré-émettre proprement les exceptions non gérées.
    • validate_or_raise(condition: bool, exception_cls: Type[PipelineBaseException], message: str, **kwargs) : Helper pour valider des assertions applicatives et lever l'exception typée correspondante.

2. Bonnes Pratiques Appliquées

  • Hiérarchie d'Exceptions Stricte : Toutes les exceptions dérivent de PipelineBaseException, permettant un filtrage et une capture ciblée dans tout le pipeline.
  • Sérialisabilité & Standardisation API : Alignement direct avec le modèle Pydantic ErrorResponse pour garantissant des réponses d'erreur unifiées sur les endpoints API / Webhooks.
  • Masquage des Données Sensibles (Sanitization) : Purge automatique des clés privées, jetons d'accès et variables d'environnement dans les messages d'erreur et stack traces.
  • Traçabilité & Chaînage de Contextes : Utilisation systématique du chaînage d'exceptions (raise ... from err) pour conserver la cause racine sans perdre le contexte d'exécution.
  • Typage Statique Complet : Annotations de types complètes (Python 3.10+) pour une validation rigoureuse via MyPy / Pyright.

3. Points Remarquables

  • Interopérabilité Native avec Pydantic : Conversion automatique entre les exceptions Python et la structure ErrorResponse du modèle core.
  • Résilience & Circuit Breaker : Integration native avec la gestion d'état du circuit breaker pour isoler les composants défaillants.
  • Prise en charge du Workflow RLHF : Exceptions de contrôle de flux permettant la mise en pause synchrone en attente de la décision d'un opérateur humain.
  • Gestion Avancée des Échecs Web3 : Decodage précis des erreurs de revert EVM et des timeouts RPC.
