⚙️ 1. Prérequis Systèmes & Guide d'Installation de l'Environnement

Afin de faire tourner le pipeline complet avec ses agents IA locaux, ses bases vectorielles et le moteur de test de sécurité blockchain, la machine hôte doit disposer des outils suivants[cite: 1, 2] :

1. Matériel & Systèmes d'Exploitation Recommandés[cite: 1]

  • OS : Ubuntu 22.04 LTS / macOS Sonoma / Windows avec WSL2 (Ubuntu)[cite: 1, 2].
  • RAM : 16 Go minimum (32 Go recommandés pour exécuter Ollama et Anvil simultanément)[cite: 1].
  • Stockage : 50 Go d'espace libre (images Docker, cache Foundry et modèles LLM)[cite: 1].

🎯 2. Description Fonctionnelle, Workflow Auto-Débogage & Rôle du Pilote (HITL)

Le pipeline agit comme une équipe d'ingénierie autonome sous le contrôle d'un Tech Lead humain[cite: 1]. Une caractéristique fondamentale du système est sa boucle de test et d'auto-débogage autonome pré-validation : aucun code n'est présenté à l'humain s'il n'a pas préalablement réussi 100 % de ses tests unitaires, d'invariants et d'audits de sécurité[cite: 1, 2].

🔄 Déroulement Strict du Workflow de Développement :
1. Génération : L'agent spécialisé produit le code Solidity ou TypeScript[cite: 1].
2. Compilation & Tests Unitaires : Le système exécute automatiquement forge test[cite: 1].
3. Bouclier de Sécurité Multi-Couches : Slither (AST), Fuzzing (Foundry), Threat Simulator (Anvil) et Halmos (Preuve Formelle) auditent le code[cite: 1, 2].
4. Boucle d'Auto-Correction (En cas d'échec) : Si une erreur de compilation ou une vulnérabilité est détectée, le système intercepte la sortie d'erreur, la réinjecte au LLM sous forme de prompt correctif et relance les tests[cite: 1, 2]. Cette boucle s'exécute jusqu'à 3 fois de manière autonome[cite: 1, 2].
5. Présentation à l'Humain (HITL) : Ce n'est qu'une fois le code totalement propre et validé par les outils déterministes qu'une notification est envoyée au Dashboard avec le diff et le lien Gist pour validation humaine[cite: 1, 2].

Rôles des Acteurs Métier[cite: 1]

  • L'Agent Architecte : Analyse le besoin, génère le DAG de tâches et identifie les compétences requises[cite: 1, 2].
  • La Dev Squad (Agents de Dev) : Rédige le code, les tests unitaires (*.t.sol) et les scripts d'invariants[cite: 1, 2].
  • Le Circuit Breaker & Auto-Debugger : Gère les tentatives de correction automatique (max 3 itérations) avant d'alerter si un blocage persiste[cite: 1, 2].
  • Le Pilote Humain (Tech Lead) : Inspecte le code déjà certifié sur le Dashboard, visualise les diffs et donne le feu vert pour le commit final sur Git[cite: 1, 2].

🛡️ 3. Bouclier Anti-Hallucinations & Mitigation des Effets Indésirables IA

Les modèles de langage (LLM) présentent des risques connus lorsqu'ils génèrent du code critique Web3[cite: 1]. Le pipeline embarque des mécanismes de protection stricts à chaque étape[cite: 1, 2] :

Effet Indésirable / BiaisSymptôme & Risque MétierMécanisme de Protection Technique
Hallucination de Syntaxe / Dépendances[cite: 1, 2] Importation de bibliothèques inexistantes ou syntaxe Solidity obsolète[cite: 1, 2]. Boucle de Compilation Déterministe : Tout code est immédiatement soumis à forge build[cite: 1, 2]. L'AST exact et l'erreur du compilateur sont réinjectés à l'agent sans passer par une auto-évaluation du LLM[cite: 1, 2].
Invention d'API / Fonctions[cite: 1, 2] Appel de méthodes absentes des standards ERC[cite: 1, 2]. RAG Vectoriel Strict (ChromaDB) : Le prompt est ancré (grounded) uniquement sur les interfaces vérifiées d'OpenZeppelin v5 stockées en vector store[cite: 1, 2]. Interdiction d'inventer des signatures[cite: 1].
Dérive de Contexte (Scope Drift)[cite: 1, 2] L'agent modifie des parties du contrat non demandées ou oublie des contraintes architecturales[cite: 1, 2]. Stateless Execution & Context Pinning : L'état réside dans PostgreSQL[cite: 1, 2]. Chaque requête est exécutée dans un contexte propre réinjectant le System Prompt invariant de la tâche DAG en cours[cite: 1].
Boucle Infinie de Refactoring[cite: 1, 2] L'agent corrige un bug mais en introduit un autre, tournant en boucle indéfiniment[cite: 1, 2]. Circuit Breaker (Disjoncteur) : Plafond strict à 3 essais de correction automatique[cite: 1, 2]. En cas de dépassement, la tâche passe en statut WAITING_HUMAN_VALIDATION / CIRCUIT_BROKEN avec le journal complet des erreurs[cite: 1, 2].
Opacité du Raisonnement[cite: 1] Impossibilité d'expliquer pourquoi l'agent a choisi une structure de données plutôt qu'une autre[cite: 1]. Audit Trail JSON : Chaque décision de l'agent est enregistrée avec sa promesse (prompt), sa réponse brute et la trace de compilation associée dans la table execution_logs[cite: 1, 2].
Auto-Complaisance IA[cite: 1] L'agent affirme que le code est sécurisé sans l'avoir réellement testé[cite: 1]. Séparation Étanche Dev vs Audit : L'évaluation est réalisée par des sous-processus système (Slither, Halmos, Anvil) externes et déterministes[cite: 1, 2]. Le LLM ne juge jamais son propre code[cite: 1].

🧬 4. Moteur d'Acquisition & Injection Dynamique de Compétences Expertes (`BaseSkill`)

Le pipeline n'utilise pas d'agents figés[cite: 1]. L'Agent Architecte conçoit des agents sur-mesure pour chaque projet en leur assemblant des compétences expertes (BaseSkill) instanciées à chaud[cite: 1, 2].

1. Anatomie d'une Compétence Experte (`BaseSkill`)[cite: 1, 2]

Une compétence est un module autonome comprenant 3 composants indissociables[cite: 1, 2] :

  • Prompt Template & Rules : Directives d'expertise métier, anti-patterns à éviter et exemples concrets (few-shot prompts)[cite: 1, 2].
  • Tooling Executable : Wrapper Python encapsulant les appels système ou CLI (ex: compilation forge, appels RPC, requêtes Slither)[cite: 1, 2].
  • Schéma Pydantic : Contrat de données strict imposant la structure des paramètres d'entrée et de sortie[cite: 1, 2].

2. Processus Pas à Pas d'Acquisition Dynamique[cite: 1]

Étape A : Cartographie du Projet par l'Architecte[cite: 1]
Lors de l'analyse du project_config.yaml, l'Agent Architecte décompose le projet en tâches DAG et liste les compétences requises (ex: ERC20VaultSkill, ChainlinkOracleSkill, HalmosProofSkill)[cite: 1].
Étape B : Interrogation du Registre (`SkillRegistry`)[cite: 1]
Le système interroge la base vectorielle ChromaDB et PostgreSQL[cite: 1]. Si la compétence existe déjà, elle est directement chargée[cite: 1].
Étape C : Synthèse Dynamique à Chaud (Si Compétence Inexistante)[cite: 1]
Si une compétence métier requise est absente du catalogue :
1. L'Architecte déclenche un méta-prompt de création de compétence[cite: 1].
2. Il recherche la documentation officielle de référence via RAG (ex: documentation Chainlink CCIP)[cite: 1].
3. Il génère la classe Python héritant de BaseSkill, avec son modèle Pydantic et ses règles de prompt[cite: 1, 2].
4. La compétence est compilée, validée et enregistrée dans le SkillRegistry pour réutilisation ultérieure[cite: 1, 2].
Étape D : Assemblage Runtime par l'`AgentFactory`[cite: 1]
L'AgentFactory prend un AgentTemplate vierge, lui injecte les compétences requises et instancie l'agent final prêt à exécuter sa mission dans le DAG[cite: 1, 2].

🛡️ 6. Shielding Sécurité Multi-Couches (Anti-Attaques Web3)

Le bouclier de sécurité exécute 4 niveaux d'analyse déterministes[cite: 1, 2]. Tout échec déclenche une réinjection immédiate de la trace dans la boucle d'auto-débogage de l'agent[cite: 1, 2].

NiveauMoteur / OutillageVecteurs d'Attaques CiblésAction en cas d'Echec
Niveau 1[cite: 1, 2] Slither / Aderyn[cite: 1, 2] Réentrance basique, variables non initialisées, re-entrancy d'état, shadowing[cite: 1, 2]. Interception de l'AST Slither -> Auto-correction Agent[cite: 1, 2].
Niveau 2[cite: 1, 2] Foundry / Echidna Fuzzing[cite: 1, 2] Violations d'invariants métier, erreurs d'arrondi, overflow d'état[cite: 1, 2]. Extraction du contre-exemple de fuzzing -> Auto-correction Agent[cite: 1, 2].
Niveau 3[cite: 1, 2] Anvil Threat Simulator[cite: 1, 2] Flash Loans, manipulation d'oracles Uniswap/Chainlink, MEV, front-running[cite: 1, 2]. Capture de la trace d'attaque Anvil -> Auto-correction Agent[cite: 1, 2].
Niveau 4[cite: 1, 2] Halmos Symbolic Prover[cite: 1, 2] Insolvabilité du coffre, brèche de logique métier multi-fonctions[cite: 1, 2]. Extraction du contre-exemple mathématique Z3 -> Auto-correction Agent[cite: 1, 2].

        proc = await asyncio.create_subprocess_exec(
            "forge", "build", "--json",
            cwd=self.project_path,
            stdout=asyncio.subprocess.PIPE,

        proc = await asyncio.create_subprocess_exec(
            *cmd, cwd=self.project_path,
            stdout=asyncio.subprocess.PIPE,
            stderr=asyncio.subprocess.PIPE
        )
        stdout, stderr = await proc.communicate()
        return {"success": proc.returncode == 0, "output": stdout.decode()}

    async def compile_and_test(self) -> Dict[str, Any]:
        comp = await self.compile()
        if not comp["success"]:
            return comp
        return await self.test()

        self.project_path = project_path

    async def create_branch(self, branch_name: str) -> bool:

                "https://api.github.com/gists",
                headers={"Authorization": f"Bearer {self.token}"},
                json={"description": "Smart Contract Dev Pipeline 2.0 - Audit Review", "public": False, "files": {filename: {"content": content}}}

class WorkflowEngine:
    def __init__(self):
        self.completed_tasks: set = set()

    async def run_pipeline(self, dag_nodes: List[Dict[str, Any]]) -> bool:
        for node in dag_nodes:
            success = await self.execute_node(node)
            if not success:
                return False
        return True

        node_id = node.get("id")
        self.completed_tasks.add(node_id)
        return True

class AutoDebugCircuitBreaker:
    def __init__(self, max_retries: int = 3):
        self.max_retries = max_retries
        self._failures: Dict[str, int] = {}

    def can_retry(self, task_id: str) -> bool:
        return self._failures.get(task_id, 0) < self.max_retries

    def record_failure(self, task_id: str, error_log: str) -> int:
        current = self._failures.get(task_id, 0) + 1
        self._failures[task_id] = current
        return current

    def reset(self, task_id: str) -> None:
        if task_id in self._failures:
            del self._failures[task_id]

📚 9. Glossaire Technique

DAG (Directed Acyclic Graph)
Graphe orienté sans cycle définissant l'ordre d'exécution topologique des tâches du pipeline.
HITL (Human-in-the-Loop)
Modèle de validation où l'humain (Tech Lead) conserve la décision finale avant publication en production.
Foundry / Forge
Toolkit de développement Solidity ultra-rapide écrit en Rust permettant compilation, fuzzing et tests unitaires.
Halmos
Prouveur formel symbolique basé sur Z3 permettant de valider mathématiquement les invariants des smart contracts.
Slither
Analyseur statique AST pour Solidity détectant les failles de sécurité et les anti-patterns.
RAG (Retrieval-Augmented Generation)
Technique combinant la recherche sémantique vectorielle (ChromaDB) et l'inférence LLM pour ancrer les réponses sur des sources documentaires vérifiées.
Circuit Breaker
Mécanisme de disjonction limitant le nombre de tentatives d'auto-débogage (fixé à 3) pour éviter les boucles infinies.
